# Travel Planning Practices — Overview

This bundle covers **how to read a travel itinerary before you pay for
it** — the consumer-diligence layer between receiving a document and
committing a deposit. A formal itinerary does two jobs at once: the
marketing lives on page one, and the contractual truth lives in the
fine print. The highest-value travel skill is reading the second layer
before money moves, not at the dock where the optional excursion is
already sold out or priced at double the independent rate.

## The Core Thesis

**An itinerary is a coded document, and the code is consistent.**
Every section — header block, day-by-day, inclusions/exclusions,
optional excursions, terms — uses conventions that mean something
specific: meal letters, activity verbs, "subject to" clauses,
per-person pricing bases. Once the code is known, a 14-page PDF
reduces to a 30-minute verification exercise that routinely surfaces
$200–500 in unbudgeted costs per trip.[^chieftourist-itinerary-reading]

The second thesis: **identify the document type before reading a
single line.** The same sentence means different things on an
escorted group tour versus a self-guided FIT package. "Day 4: Chiang
Mai" is a fully-managed day on the first and a hotel voucher plus a
phone number on the second. [Itinerary Types](itinerary-types.md) is
the entry point; everything else in the bundle reads through it.

The third thesis: **the document is the start of a negotiation, not
the end of one.** Every ambiguous line converts into a numbered
written question to the operator, and the written answers become part
of the booking record. The
[Pre-Booking Verification Workflow](pre-booking-verification-workflow.md)
is the deliverable the whole bundle feeds.

## The Reading Order

The disciplines chain in the order a document is actually read:

```
type → header codes → day-by-day verbs → transit reality →
inclusions/exclusions → optionals → conditional clauses →
pace/hotels/guiding → verification questions
```

| Stage | Practice | What it prevents |
|-------|----------|------------------|
| Identify | [Itinerary Types](itinerary-types.md) | Reading a self-guided voucher package as if a guide handles everything |
| Decode | [Itinerary Verb Decoding](itinerary-verb-decoding.md), [Meal Codes and Gap Budgeting](meal-codes-and-gap-budgeting.md) | Expecting entry where the document only promises a drive-past; unbudgeted meals |
| Price | [Pricing Codes and Solo Supplements](pricing-codes-and-solo-supplements.md), [Inclusions and Exclusions Analysis](inclusions-exclusions-analysis.md), [Optional Excursions Trade-Off](optional-excursions-tradeoff.md) | Comparing tours on headline price instead of all-in cost |

## Scope

- **Covers**: reading operator/agent-issued itineraries and excursion
  sheets — document types, coded language, inclusions/exclusions,
  optional excursions, conditional activities, pace and timing
  reality, pricing conventions, and pre-deposit verification.
- **Does not cover**: choosing destinations, booking flights, travel
  insurance selection, loyalty/points strategy, or post-booking trip
  execution (packing, visa application mechanics, on-trip spending).
- **Source basis**: currently grounded in a single consumer
  travel-literacy source; subsequent ingests should add operator
  terms-and-conditions samples and regional fee schedules (visa,
  tourist tax) as first-class sources.

## How the Bundle Grows

New sources — operator T&Cs, destination fee schedules, cruise-line
excursion policies, consumer-protection rulings — are ingested as
concept updates and new pages, never as article-comparison sections.
Each page stays a normative practice with its own `sources:` list;
corrections to a practice fold in next to it rather than living in a
separate rebuttal block.
